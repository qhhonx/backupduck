# Android 全部功能原生复刻范围

2026-10-03。浏览器管理常规流程已获用户认可，采用它的组件契约与验收流程作为后续基准。代码保持未提交；不会据此发布正式版本。当前原型与代码清单包含 56 个应用界面（23 个页面、23 个弹层、10 个确认框），另有 6 个系统 / 外部边界和 1 个评审组件示例。

## 实施顺序

| 顺序 | 功能域 | 必须一起核对的范围 |
| --- | --- | --- |
| 1 | 接收与配对 | 首页、连接设备、二维码、扫描入口；未启动、启动中、启动失败、权限拒绝、配对结果与恢复 |
| 2 | 传输 | 列表、筛选、类型与来源选择、状态说明、单项详情；加载、空列表、失败重试、暂停、高温和实时更新 |
| 3 | 存储与原件 | 明细、空间限制、保留策略、自动回收范围、历史检查、检查结果、回收确认与结果、导出和校验 |
| 4 | 设置与设备 | 温度、兼容转换、设备名称、发送设备列表与权限确认、外观、语言；设置保存、取消、失败与持久化 |
| 5 | 帮助与诊断 | 帮助首页和五个主题、更新全部状态、诊断、日志保留、报告导出、停止接收确认 |
| 6 | 实验功能 | 自动释放空间、账号绑定、授权说明、检查进度、结果核对、相册页面诊断与报告；保留既有权限与安全边界 |

分功能域实施是为了定位问题，最终范围仍是全部 Android 功能。完成一个域后继续下一域，不能用一级页面完成代替整个应用完成，也不能以一个通用页面取代原型中不同的信息结构。

## 每个域的完成定义

- 对照 `catalog.json` 与真实入口，保持已有功能可达；缺少设计或设计遗漏真实功能时，先补原型再实现。不得自行补一套页面风格。
- 按原型代码还原信息层级、动作、状态与动效；全部弹层、确认、输入、说明、短反馈和持续错误复用经过验收的组件。
- 正常、加载、成功、失败、取消和重试有真实逻辑对应；不把模拟状态或样本数据写进产品界面，不改变原件 / 相册 / 云端的成功边界。
- 扩充 `verify-android-ui.py` 的原生覆盖和真实接口检查，保存浅深色、窄屏大字体以及交互后实际窗口截图；检查列表虚拟化、刷新和滚动状态。
- 更新覆盖清单与证据。区分“已实现”“自动检查通过”“Pixel 真机检查”“用户验收”，不能合并成一个完成标记。

Android 通知 / 相机权限、二维码扫描相机、文件选择器、安装权限、系统无障碍设置以及 Google 相册本身保留系统或外部界面。复刻的是应用的进入说明、返回与失败恢复，不能伪造这些系统界面。评审组件页不是新增产品功能。

浏览器管理已认可的布局保持为基准。其余平台在 Android 全面检查完成后再推进；本轮仍仅安装独立 Pixel 验收应用，保留正式应用及数据，不提交或推送代码。

## 本轮实施记录（2026-10-04）

六个功能域的自有页面、弹层与确认框均已迁移；共用组件负责标题、间距、输入、选择、说明图标、按钮和反馈，页面不再分别创建另一套临时弹窗。原型源代码与真实接口核对后同步修正了配对码状态和设备名称长度。

`FullReplicaCheck` 检查配对启动 / 失败 / 重试、温度和转换设置、名称校验、发送设备、空间限制、回收范围、导出入口、诊断、实验授权取消与更新页；`StorageUiCheck` 单独验证真实持久配置及取消语义。浏览器组件、传输列表和帮助检查继续保留。检查截图仅用于开发内部，用户在 Pixel 验收。

真实照片的大批量接收、系统相机 / 文件选择 / 安装权限、实际导出回收、Google 相册和无障碍实验的全流程仍需要对应实测，不由布局矩阵代替。仅安装独立验收包，不提交、推送或发布。
