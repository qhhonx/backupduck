# Android 原型还原实施与验收流程

2026-10-04。浏览器管理试点获得认可后，扩展到全部 Android 应用自有界面。实现、自动检查、Pixel 真机检查与用户验收分别记录。

## 每项功能如何交付

1. **盘点实际功能**：从真实入口走完整流程，与 `catalog.json` 核对。列出二三级页、弹窗、系统跳转，以及正常、加载、成功、失败、取消、重试；缺设计先补原型。不能把旧功能丢掉，也不能根据截图自行发明细节。
2. **提取组件契约**：读原型代码，记录内容顺序、固定与滚动区域、字号行高、相邻间距、图标对齐、动作层级、每种状态的说明和反馈宿主。页面只组合共用组件；例外要写明理由。尺寸写入 `specification.md`，不靠截图猜数值。
3. **先验证组件，再组页面**：优先修复共用组件。组件检查使用中文、英文、多行和大字体；验证的是实际画出的文字与图标，而非只有 View 外框。短反馈属于当前窗口，不能挂到被弹窗遮住的页面。
4. **从入口走状态转换**：点每个按钮，检查业务结果、用户能看到的结果和返回后的状态。复制要检查剪贴板内容及弹窗内提示；保存要检查持久结果、禁重与提示；失败要保留输入和恢复动作；取消不能丢失草稿。仅证明接口调用过或文案存在不算通过。
5. **分开验证自动检查与视觉检查**：运行下面的矩阵，检查实际窗口截图。与原型对照结构、密度、字形、图标、间距、按钮位置、说明完整性、可见反馈。截图不能代替动态流程，自动断言不能代替人工视觉检查。
6. **最后进行 Pixel 真机检查**：旧 Pixel 的系统中文字体、键盘、返回手势、截图保护和接收中的性能。无法检查的项留在验证记录；不得写成通过。用户做最终设计验收，我承担交付前的结构、组件与流程检查。

## 可重复运行的原生检查

启动已配置的独立模拟器，设置 Java / Android SDK 环境后运行：

```sh
python3 scripts/verify-android-ui.py --serial emulator-5554
```

脚本只接受模拟器，安装独立 `.validation` 包；覆盖 411dp / 标准字体与 320dp / 2 倍字体的浅深色四个组合。构建和单元测试、原生组件流程、完整改版代表流程、真实存储配置与访问码接口分别留日志；另检查 200 条传输记录的虚拟化、稳定布局和五个帮助主题。各组合保存实际窗口截图，输出报告带 APK 校验值与代码版本，用户验收保持 pending。结束还原模拟器显示设置；不访问真实接收手机的数据。

| 门槛 | 组件与完整改版的证据 |
| --- | --- |
| 原型完整性 | `catalog.json` / `prototype.js`，`tests/android_design_prototype.cjs`；不证明原生已经完成 |
| 内容与顺序 | 标签在框外，复制在卡片下方，重置为描边动作，三个必要说明块；间距与提交区断言 |
| 图标与文字 | 说明、简短注释和错误统一首行对齐；检查实际绘制的图标与第一行字形中心 |
| 操作反馈 | 剪贴板内容正确，短提示确实在当前弹窗窗口内可见并完整显示 |
| 状态转换 | 启动、错误持续保留、重试、保存禁重、取消保留草稿、保护开关；合成接口与真实 JNI 分开检查 |
| 实际截图 | 原生窗口截图，包括点复制后的瞬间；浅深色和窄屏大字体；记录明确区别模拟器与 Pixel |
| 用户验收 | 单独记录；自动检查通过不能代替用户认可 |

后续每增加一个页面或状态，就扩充契约和检查；当前矩阵验证代表流程，不等于所有原型状态的业务结果。每次用户反馈应修复共性原因并补回归检查，不仅改截图里的那一处。

## 回归问题必须留下的证据

本轮检查实际发现并修复了两类共性问题：横向按钮按文字基线对齐会让换行按钮越出父容器；隐藏的原生 Dialog 的 `isShowing` 为 false，因此不能以它判断是否恢复上一弹层。前者在共享动作区关闭基线对齐，保留实际可见边界断言；后者按宿主生命周期恢复，存储检查实际走取消 / 保存 / 恢复路径。

短反馈检查等待真实入场动画完成，仍断言整个提示文字可见，并核对剪贴板；不用固定休眠的中间帧当作最终布局。失败检查保存实际窗口与崩溃日志。检查代码清理已被系统移除的旧窗口时，先核对其附着状态，避免清理异常覆盖原始失败。

后续保持四份记录分开：源代码组件契约、界面 / 状态清单、自动检查的具体覆盖、用户真机验收结果。增加入口或状态时同步更新对应清单和检查；发现共性问题优先改共享组件，并对所有使用它的页面做回归。
