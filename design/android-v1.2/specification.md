# Android 完整流程设计 v1.2 · 待验收草案

2026-10-03，基于 RC.3 `8ef789c` 与当前未提交原生改版。仅 Android；v1.1 的颜色、品牌和视觉方向保留。此版本补齐功能、组件与状态，尚未替代用户已批准的四端基准。未提交、未发布。

## 功能先于画面

`catalog.json` 是页面与状态清单，`catalog.js` 是其浏览器数据副本，两者必须一致。每项包含稳定 ID、真实功能文件、入口 / 函数、组件类型、适用状态、原生实现进度。原型的 63 项是设计界面与系统边界，不是 63 个已实现原生页面。状态预览覆盖 182 种组合；只说明可渲染，不代表真实业务已验证。

从真实入口逐项核对：四个主页，帮助、设置与诊断入口，列表行 / 筛选 / 更多菜单，导出 / 回收确认，实验功能与系统跳转。低频入口可以重新组织，但不能静默删除。新增功能先补清单、页面和状态，再实现。

本原型不访问网络、相机、文件或真实设备，所有码、地址、时间、空间和照片均为合成示例。云端状态不模拟成功；不将调用请求成功当作相册处理成功。

## 组件标准

| 组件 | 唯一使用规则 | 尺寸与行为 |
| --- | --- | --- |
| 页眉 | 主页面标题；二三级页面带返回。帮助与更多使用图标按钮 | 56dp；标题 24sp / 粗体，视觉图标 22dp，命中区域 48dp；禁止用字形代替图标 |
| 底部导航 | 仅四个主页显示；次级全页使用返回，不重复底栏 | 常规高度 80dp，含 8dp 顶部 / 12dp 底部；32dp 胶囊与标签独立排列，间距至少 4dp；大字体按内容增长 |
| 设置分组 | 左侧标题与说明，右侧值 / 开关 / 箭头 | 圆角 12dp；行高至少 64dp；标题 16sp / 粗体，辅助 13sp；控件不得覆盖文字 |
| 底部弹层 | 详情、短表单、选择器、说明 | 圆角 20dp；顶部拖动条 36×4dp，关闭按钮 48dp；正文可滚动，提交区域固定于底部；高度按内容，最多可用窗口 88% |
| 确认框 | 短确认，如重置访问码、撤销登录、更改接收权限 | 20dp 圆角，屏幕左右至少 24dp；取消与确认并排，文字可换行；超过 1.3 倍字体时纵向排列，正文可滚动；危险操作用语义失败色 |
| 次级全页 | 多步骤任务、设备列表、帮助主题、更新、诊断、实验 | 原生返回栈；正文滚动，保留操作状态；不把复杂任务塞入连续多重确认框 |
| 输入框 | 编辑名称、访问码等 | 高度至少 56dp；标签始终可见，错误紧邻字段；提交中禁用重复提交，失败留在原界面并可重试 |
| 短提示 | 复制、已保存、已提交等无需后续处理的反馈 | 应用内 Snackbar；不得覆盖底部导航或键盘；重要错误不用 Toast 承担 |
| 说明与错误图标 | 共用 message 组件；不是逐页添加 ImageView 和固定顶部偏移 | 视觉 18dp、与文字相距 8dp；中心对齐首行实际字形，中文 / 英文 / 多行 / 大字体均遵守；不随整块多行文字垂直居中 |
| 持续反馈 | 保存失败、启动失败、处理失败等 | 当前操作位置的错误块，含原因与恢复动作；不得自动消失或先关闭弹窗再报错 |
| 长任务 | 历史检查、导出与验证、清理观察 | 独立页面显示业务阶段；未知进度不用伪造百分比；取消只停止后续动作，已完成结果仍保留 |
| 系统边界 | 相机 / 通知权限，文件选择，安装，无障碍设置，Google 相册 | 保留系统 / 外部界面；明确进入目的、取消返回、失败恢复。不复制一张假的系统页面作为自定义产品 UI |

本次导航从 62dp 调整到 80dp，是明确的 Android 尺寸修正：原 Material 导航的内部图标 / 标签几何未随外层压缩，造成旧 Pixel 重叠。其他三端导航不随此修改。图标沿用原型 `paths` 里的统一 24×24 坐标和 1.7 圆头描边；`info` 已改为同一圆与单线 i，避免旧向量把 i 绘成双描边。

短提示必须属于操作发生的当前窗口：弹窗未关闭时在弹窗内显示；弹窗关闭后在页面显示。不允许将弹窗内复制反馈加到底下被遮挡的 Activity。反馈验收必须实际点击，并检查用户可见和业务结果，而非只检查已调用 Snackbar。

原型按 1 CSS px 对应 1dp 展示，文字按原生字号；并排桌面审阅不再用 10px 字体压缩手机。Android 系统字重、字体和开关由原生提供，差异必须在对照记录中标明，不能自行改变信息层级。

## 弹层间距与内容契约（本轮补齐）

以原型 `prototype.css` 与四个 browser 弹层的 DOM 顺序为依据。相邻块只取一个间距，不把前块下边距与后块上边距相加；隐藏块不占高度。普通字体时按内容自然测量，超出可用高度的 88% 才滚动，不强制填满 82% 的屏幕，也不将正文撑开形成空白。

| 关系 | 原生尺寸与规则 |
| --- | --- |
| 拖动条 / 页眉 / 正文 | 拖动条顶距 12、底距 16；页眉关闭命中区 48，底内距 4；正文顶部内距 8、左右 20、底部 20 |
| 说明段落 → 地址卡片 | 段落行高 1.5；段落顶部 8，段落后到卡片 16 |
| 地址卡片内部 | 每行左右 14、上下 12，标题行高 1.4；标题与值间距 4；行高至少 64 |
| 地址卡片 → 复制按钮 → 安全说明 | 卡片后 20，复制按钮后 16；复制按钮属于正文，与卡片同宽；安全说明后 16，随后正文底内距 20 |
| 表单说明 → 标签 → 输入框 | 说明后 16；标签始终在框外，13sp；标签与输入框 8；输入框至少 56 高、内距 12、圆角 8；不使用框内占位或浮动标签替代固定标签 |
| 输入框 → 状态说明 → 重置按钮 | 输入框后 16；状态说明后 18；重置是整行描边按钮，文案“重置为随机访问码” |
| 提交区 | 仅原型有 footer 的表单 / 确认框固定底部；顶部 1dp 分隔线；内距上 12、左右 20、下 20；按钮间距 8 |
| 确认框 | 左右距屏幕 24；标题外距上 / 左 / 右 20；正文内距上 12、左右 / 下 20；正文首段上距 8、段落与说明卡片 16；说明后 16 |

信息完整性是验收项：设置访问码显示“设置不会立即改变现有备份任务。”；重置确认显示“不会改变设备配对和备份任务。”；退出浏览器确认显示“下次访问需要重新输入访问码。”。写入时由进行中说明替换，失败时由持续错误替换，不能省略整块说明。

重置确认与输入表单不同时叠放；取消确认返回原表单并保留草稿，重置成功后关闭旧表单。

验收包只有访问码行内的“显示 / 隐藏”辅助动作，默认遮蔽；不添加大块验收提示和整行调试按钮改变设计稿层级。输入框本身的密码遮蔽不增加额外说明卡片。正式应用仍保留截图保护。

## 浏览器管理试点

设置 → 浏览器管理 → 开启 / 关闭 → 访问地址与码 → 复制地址 → 设置新码 → 输入错误 / 保存中 / 失败重试 / 成功 → 重置码确认 → 撤销登录确认。

- 关闭浏览器管理不改变发送设备配对。
- 访问码为 10 位数字，在重启与更新后保持。
- 新码或随机重置使现有浏览器重新登录，不改变发送设备认证。
- 撤销登录不修改访问码。失败不误报成功，保留旧配置。
- 接收未启动或没有地址时，不编造 URL；提供启动 / 网络恢复入口。
- 正式应用的访问码弹层使用 `FLAG_SECURE`。独立 `.validation` 验收包默认遮蔽访问码并允许截图，输入框始终遮蔽每位数字；主动显示真实码时重新开启截图保护，隐藏后才允许截图。此例外只用于本地验收，不影响正式应用。公开证据仍使用注入的合成响应；实际接口验证单独记录。
- 开始接收立即显示启动提示；服务失败持续显示具体原因及重试，不随后台自动重试闪烁；接收和浏览器服务都启动成功才显示可访问。验收包使用独立接收端口 48484，正式应用使用 8484，两者可同时运行。
- 编辑失败留在输入弹层；确认失败留在确认框。短提示只在已确认成功后出现。

## 状态和动效

沿用 v1.1 的原件接收 / Pixel 相册保存 / Google 云端三个事实边界。缺失日期不补造；有视频时长显示时长；温度恢复条件来自真实业务。概览计数是历史总计时写“接收概况”，不称为未定义的“本批”。

文字反馈 120ms，遮罩 140ms，底部弹层进入 220ms / 12dp、退出 160ms / 8dp，进度插值 320ms。减少动效时立即更新。系统操作与动画不强行重制。点击取消、系统返回与关闭按钮具有同一语义；写入期间禁用退出和重复提交，结束后恢复。

## 实现与验收门槛

1. **覆盖**：所有真实入口在清单里找到；不是仅保证一级页面可访问。新增 / 遗漏功能记录差异，先补设计。
2. **组件**：试点不直接创建临时 Toast 或另一种 AlertDialog；组件参数、图标、间距和动作布局统一。
3. **流程**：从真实页面入口走到保存、取消、失败和重试；模拟注入不能代替接口验证。
4. **几何**：320 / 360 / 411dp、正常与大字体、浅深色、键盘；图标与标签不相交，页底提交不被遮挡，长文案可达。
5. **行为**：返回关闭后焦点与滚动位置保留；重复点击不重复请求；失败不改成功状态；开启与关闭后实际配置一致。
6. **证据**：代码对照 + 实际窗口截图 + 操作记录。网页测试、编译与截图分别记录，均不能直接标用户验收通过。

浏览器管理常规流程已获得用户认可；2026-10-04 同一组件与流程标准已用于全部 Android 自有界面。用户直接在 Pixel 进行本轮验收，不交付截图集合代替手机体验。Android 验收通过后才扩展 iOS / Mac / Web。

## 完整原生迁移的补充契约（2026-10-04）

- 所有短表单复用 `DuckField`，固定外置标签、56dp 最小高度、12dp 输入内距；选择框复用 `duckSelect`，56dp 外框和独立下拉图标。
- 确认框和多动作弹层在标准字体下横向排列，超过 1.3 倍字体纵向排列。横向容器关闭文本基线对齐，按按钮整体居中测量，避免英文换行把按钮移出父容器；动作高度随内容增长。
- 次级全页复用 `DuckPage`，设置与信息行复用 `duckSetting`，错误 / 短反馈使用当前操作窗口的统一组件。选择自动回收范围时暂时隐藏保留策略弹层，取消或保存后恢复，避免叠层和草稿丢失。
- 设备名称以真实 Rust 接口为准：去除两端空白后 1–40 个 Unicode 码点，并拒绝控制字符与双向文字控制符。不能沿用原型旧的 64 字符示例来允许后端必然拒绝的值。
- Pixel 发给 iPhone 的配对码表示当前接收身份，协议没有过期字段；原型“已过期”改为“接收不可用”，刷新只重新读取实际码。Mac 邀请码仍按协议校验真实有效期。
- 存储读取失败显示缺失值和恢复入口，不用零代替未知原件 / 未完成文件量。未知时间、温度、相册结果仍保留真实缺失状态。
- 云端正在准备不触发转换；释放原件仍要求既有副本核对，导出仍要求 ZIP 回读校验。UI 迁移不能越过原有权限、确认与完整性检查。
