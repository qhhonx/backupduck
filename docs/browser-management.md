# Receiver browser management

The Android receiver can host a management page for a computer on the same Wi-Fi network. In **Settings → Advanced settings → Browser access**, enable the switch while receiving is running, then open the displayed address on the computer and enter the code shown on the Pixel. The page shows received, waiting, gallery-published, and failed totals; battery temperature, charge level, available storage, and BackupDuck original usage; a status guide; and a filterable transfer table. The battery temperature is Android's battery-sensor reading, not a CPU temperature. The displayed heat-pause state comes from the receiver's existing thermal control. **Retry failures** asks the receiver to process its retained originals again. Auto refresh runs every eight seconds while the page is visible and can be turned off. Page 1 updates automatically; older pages stay in place until manually refreshed, while the overview continues updating.

The table shows the file, status, sender's capture time, and size. Click the filename for a detail view with the sender, media type, three local timestamps, receive progress, retained-original status, and any processing hint. A burst frame is recognized from the sender's burst-group metadata and labeled separately from a motion photo; it can also be filtered in the browser. Receive-complete and gallery-publication timestamps are recorded starting with beta.30; older records show **Not recorded** instead of an inferred time. Capture time is unavailable when the sender did not provide it. These times describe local transfer and gallery handling, not Google Photos cloud upload. Filters and numbered pagination run on the receiver before results are returned. The table offers 20, 50, or 100 items per page, page numbers, first/previous/next/last controls, and direct page entry.

This page manages the **Pixel receiver**, not the iPhone or Mac sender queue. A transfer marked **Added to phone gallery** has passed Android gallery publication; it does not prove that Google Photos uploaded the item to the cloud. The page does not expose photos or originals for download.

The feature is off by default. Its listener exists only while receiving and browser management are both on, and it binds to the receiver's current Wi-Fi IPv4 address on port 8485. The transfer service remains on its separate paired HTTPS port 8484. Browser management uses **plain HTTP** to avoid a self-signed certificate warning in ordinary browsers, so the address, access code, and session traffic are not encrypted. Use it only on a trusted private Wi-Fi; turn it off on public or shared networks. A new 10-digit code and independent session token are generated whenever the listener starts. Five wrong code attempts trigger a five-minute lockout. Disabling the switch or stopping the receiver closes the listener and invalidates the session.

The page bundles its assets locally, requires a code before returning status or history, checks the numeric Host and Origin headers, does not enable cross-origin requests, and returns `no-store` responses. It does not share the transfer pairing token. A different device on the same trusted Wi-Fi can reach the HTTP port if it knows the code; this is not remote Internet access or a cloud relay.
